# AKI Medallion Lakehouse

A clinical machine learning pipeline for early prediction of **Acute Kidney Injury (AKI)** in ICU patients, built on a Medallion lakehouse architecture using DuckDB, scikit-learn, and XGBoost.

The pipeline ingests MIMIC-IV FHIR data, applies KDIGO 2012 clinical criteria, engineers hourly temporal features, and trains models to predict AKI onset **up to 6 hours in advance**.

## Architecture Overview

The pipeline follows the **Medallion architecture** pattern, it processes data through three progressive layers:

| Layer | Script | Purpose |
|-------|--------|---------|
| **Bronze** | `pipeline/jobs/bronze.py` | Ingests raw MIMIC-IV FHIR NDJSON files into DuckDB with minimal transformation |
| **Silver** | `pipeline/jobs/silver.py` | Applies KDIGO 2012 AKI criteria; computes 7-day rolling creatinine baselines; labels AKI events |
| **Gold** | `pipeline/jobs/gold.py` | Resamples to an hourly grid per stay; forward-fills clinical values; computes staleness indicators; generates the `aki_within_6h` prediction target |

The resulting `gold_hourly_clinical` table contains **2,304,561 hourly observations** across **72,082 ICU stays** and is the direct input to all machine learning experiments.

## ML Pipeline

### Data Split
Patient-level 80/20 train/test split using `GroupShuffleSplit` (grouped by `stay_id`) to prevent temporal data leakage.

- **Training set:** 1,842,484 samples (57,665 stays)
- **Test set:** 462,077 samples (14,417 stays)
- **Positive class rate:** ~9.58% in both partitions

### Feature Set (18 features)
- **1** temporal index: `hr_index` (hours since ICU admission)
- **6** clinical signals: creatinine, BUN, heart rate, MAP, urine output (hourly and weight-normalized)
- **4** staleness indicators: hours since last real measurement for creatinine, BUN, heart rate, MAP
- **3** static demographics: age (clipped at 90), admission weight, gender (binary-encoded)
- **4** comorbidity flags: CKD, diabetes, congestive heart failure, sepsis

### Models
| Model | Class Imbalance Handling | Scaling |
|-------|--------------------------|---------|
| Logistic Regression | `class_weight='balanced'` | StandardScaler on 13 numeric features |
| XGBoost | `scale_pos_weight` (neg/pos ratio) | None (tree models are scale-invariant) |
| KDIGO Baseline | — | — (purely reactive, zero lead time) |

### Evaluation
- **Primary metric:** AUPRC (Area Under Precision-Recall Curve)
- **Secondary metrics:** AUROC, precision, recall, F1 at optimized decision threshold
- **Clinical metric:** Lead-time analysis — hours of advance warning before KDIGO onset

## Getting Started

### 1. Install dependencies
```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Run the pipeline
```bash
cd pipeline
python main.py
```

Or with Docker:
```bash
docker-compose up
```

### 3. Run the notebooks
Open the notebooks in order using Jupyter:
```bash
jupyter notebook notebooks/
```

### 4. Run layer validation tests
```bash
jupyter notebook tests/
```

## Data Source

This project uses the **MIMIC-IV** dataset (Medical Information Mart for Intensive Care), accessed through its FHIR-formatted export. Access requires credentialed registration via [PhysioNet](https://physionet.org/). The raw data files are not included in this repository.
